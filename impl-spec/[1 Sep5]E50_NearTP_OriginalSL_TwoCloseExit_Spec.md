# E50 → ближняя маржинальная зона: исходный стоп и подтверждённый досрочный выход

Версия: 2026-09-05. Идентификатор: `E50_NEAR_TP_ORIGINAL_SL_EXIT_2C`.

Самостоятельная спецификация для реализации причинно-корректного бэктеста. Эта версия сохраняет логику provisional ZigZag и входа по дневным клиринговым закрытиям, использует ближний тейк, исходный стоп из исследованного HTML-бэктеста и досрочный выход после двух последовательных закрытий за исходным E50 в сторону вершины.

## 1. Основные решения

| Элемент                         | Правило                                                                            |
| ------------------------------- | ---------------------------------------------------------------------------------- |
| Якорь зоны                      | Текущий provisional candidate ZigZag, известный на момент решения                  |
| Сигнал входа                    | Два последовательных валидных дневных закрытия пересекают E50 в сторону зоны       |
| E50                             | Половина расстояния от якоря до середины зоны                                      |
| Тейк                            | Ближняя граница `MZ0`                                                              |
| Исходный стоп                   | `SL = 2 × actual_entry_price − origin_MZ100`                                       |
| Досрочный выход                 | Два последовательных дневных закрытия после входа за исходным E50 со стороны якоря |
| Реакция на обновление candidate | `KEEP_OPEN`: позиция и сохранённые уровни не меняются                              |
| Позиции                         | Максимум одна открытая позиция на инструмент                                       |

«Исходный стоп» означает фактическую формулу из исследованного бэктеста. Это НЕ стоп на вершине, НЕ стоп на полпути к вершине и НЕ симметричный стоп относительно нового ближнего тейка. В этой версии принудительное закрытие при обновлении candidate отключено.

## 2. Данные и переиспользуемые компоненты

Без изменений использовать существующий `ZigZagTracker`, расчёт FMZ/IMZ, инструментальные данные, календарь клиринга/rollover, правила валидности и непрерывности дневных точек, модель спреда, комиссии и проскальзывания.

H4 используется для ZigZag. Для сигналов использовать исключительно дневные клиринговые/rollover закрытия, а не произвольное закрытие H4 или календарное UTC-закрытие. Для исполнения и очередности касаний использовать минимальный доступный таймфрейм или тики.

Нормализовать время свечей явно: `bar_open_time`, `bar_close_time`. Если исходный timestamp обозначает начало свечи, её close/high/low доступны только по завершении свечи. Дневной close не должен случайно подменяться close следующей H4-свечи.

## 3. Геометрия зоны и E50

`dFMZ` — расстояние до ближней границы; `dIMZ` — до дальней. Требуется `0 < dFMZ < dIMZ`.

Для provisional high H:

```text
MZ0   = H - dFMZ
MZ100 = H - dIMZ
MZ50  = (MZ0 + MZ100) / 2
E50   = (H + MZ50) / 2
direction = SHORT
```

Для provisional low L:

```text
MZ0   = L + dFMZ
MZ100 = L + dIMZ
MZ50  = (MZ0 + MZ100) / 2
E50   = (L + MZ50) / 2
direction = LONG
```

В коде: `mid_price = mz50_price = MZ50`; `e50_price = E50`. Для входа и досрочного выхода используется E50, не MZ50. MZ100 нужен для исходного стопа, но не является тейком этой версии.

## 4. Причинность и версии зоны

1. `ZigZagTracker` обрабатывает только завершённые H4-свечи. Candidate и его новая версия становятся известны на close соответствующей H4-свечи.
2. При поиске high использовать текущий running high, при поиске low — running low. До установления направления ZigZag не торговать.
3. Строго более высокий high или более низкий low создаёт новую версию candidate и зоны. Равный экстремум может обновить индекс, но не цены уровней и не ценовую версию candidate.
4. Изменение FMZ/IMZ или других ценовых входов также создаёт новую неизменяемую версию зоны.
5. Версия доступна для входных наблюдений только строго после `known_time`. Обе точки пересечения должны относиться к одной версии.
6. При смене версии сбрасывать базу пересечения для новых входов. Старые версии не пересчитывать задним числом.
7. Подтверждение pivot не требуется для входа. Кандидаты, которые не стали подтверждёнными pivot, и их сделки остаются в истории.
8. Сделка хранит свою исходную версию независимо от её последующей деактивации. Обновление candidate, подтверждение pivot, смена направления ZigZag и изменение маржинальных расстояний не меняют открытой сделки и её счётчика досрочного выхода.

## 5. Вход

Объект наблюдения:

```text
DailyClose(session_id, time, price, valid, continuity_key)
```

Два закрытия должны быть валидными, последовательными по календарю инструмента и строго после `zone.known_time`, при одной активной версии зоны. Пропущенная ожидаемая сессия или невалидное наблюдение разрывает пару. Выходные и праздники без ожидаемого закрытия не являются пропусками. Не использовать фиксированное ограничение в 24/72 часа вместо календаря.

```text
SHORT: previous_close > zone.e50_price AND current_close < zone.e50_price
LONG:  previous_close < zone.e50_price AND current_close > zone.e50_price
```

Равенство уровню нейтрально: такая точка не образует пересечение и разрывает пару строго противоположных закрытий. Пересечения в сторону якоря и внутридневные пересечения сами по себе не создают вход.

`signal_time` — момент, когда второе закрытие стало известно. Вход выполняется по первой исполнимой цене после получения сигнала; одна временная метка допустима только при доказуемом порядке «сигнал известен → исполнение». Не заполнять вход задним числом по E50 или по уже прошедшему закрытию.

Пропускать вход, если фактическая цена уже достигла или прошла ближний тейк:

```text
SHORT: entry_price <= origin_MZ0
LONG:  entry_price >= origin_MZ0
status = entry_beyond_target
```

В сигнальной модели фиксировать различие между временем сигнала и фактического исполнения. При некорректной геометрии SL/TP пропускать сделку с диагностикой `invalid_trade_geometry`.

## 6. TP, исходный SL и размер риска

После исполнения входа скопировать исходные уровни зоны в сделку и вычислить:

```text
E  = actual_entry_price
TP = origin_MZ0
SL = 2 * E - origin_MZ100

initial_risk   = abs(E - SL)
initial_reward = abs(TP - E)
initial_RR    = initial_reward / initial_risk
```

Для LONG должно выполняться `SL < E < TP`, для SHORT — `TP < E < SL`. Риск и потенциальная прибыль положительны. При корректной геометрии `initial_RR < 1`: стоп сохраняет расстояние до дальней границы, а тейк расположен ближе. Не восстанавливать 1:1 перемещением стопа.

TP, SL, origin_E50, anchor и origin_MZ100 после входа неизменяемы. Округление цен — по существующей tick-size политике, значения до и после округления сохранять для диагностики.

Основное сравнение выполнять при одинаковом фиксированном объёме сделки, как в предварительном анализе. Если нужен дополнительный прогон с фиксированным денежным риском, явно выделить его отдельно и рассчитывать объём по расстоянию до этого SL. Не менять размер позиции скрытно вместе с правилом выхода.

## 7. Досрочный выход: два закрытия за E50

Проверяется E50 исходной сделки, а не текущей активной зоны:

```text
adverse(close):
    LONG  -> close.price < trade.origin_e50_price
    SHORT -> close.price > trade.origin_e50_price
```

Состояния: `CLEAR`, `WARNING`, `EXIT_PENDING`. При входе — `CLEAR`. Учитывать только дневные закрытия с временем строго после фактического входа. Сигнальная точка входа не может быть первым предупреждением.

### Переходы

| Состояние | Новое дневное закрытие | Действие |
|---|---|---|
| CLEAR | Валидное adverse | WARNING; сохранить первую точку |
| CLEAR | Равенство E50 или сторона зоны | Оставить CLEAR |
| WARNING | Следующая по календарю валидная точка adverse | EXIT_PENDING; сохранить подтверждающую точку и отправить рыночный выход |
| WARNING | Следующая точка на стороне зоны или ровно E50 | Сбросить в CLEAR |
| CLEAR/WARNING | Невалидная точка или пропущенное ожидаемое закрытие | Сбросить в CLEAR |
| EXIT_PENDING | Новые цены/закрытия до исполнения | Не отменять подтверждённый выход |

Если разрыв обнаружен только при поступлении новой валидной точки, сначала сбросить старое предупреждение. Новая adverse-точка может стать первым предупреждением новой пары, но не подтвердить старую.

Одна сессия учитывается один раз. Дубликаты не увеличивают счётчик; конфликтующие дубликаты обрабатываются правилами качества данных. Условие проверяется по закрытиям: внутридневной возврат на сторону зоны не сбрасывает WARNING, если следующее дневное закрытие снова adverse.

### Исполнение

```text
exit_reason = e50_two_close_return
exit_signal_time = confirming_close.known_time
exit_price = first executable market price after signal is known
```

Логическое решение принимается на втором закрытии. Исполнять по уже известному close задним числом запрещено. Если источник содержит только цены дневного закрытия, оценку «fill = second_close.price» разрешено выводить лишь отдельным диагностическим сценарием с пометкой `close_price_proxy`, не как исполнимый основной бэктест. Для основного прогона нужны доступные после сигнала котировки или open следующего доступного бара с моделью расходов.

Не ждать третьего дневного закрытия для исполнения подтверждённого выхода. При закрытом рынке исполнить на первой доступной котировке после открытия.

## 8. Приоритет TP/SL и событий

TP и SL работают постоянно, включая первый день предупреждения и следующий день до подтверждения. Если позиция закрылась по TP/SL, удалить WARNING/EXIT_PENDING и не создавать второй выход.

Хронологический порядок:

1. Исполнить ранее доступные выходы и обработать касания TP/SL согласно фактическому порядку котировок.
2. Завершить бар/сессию и сделать её данные доступными. Сначала учесть TP/SL, достигнутые до или на данном закрытии.
3. Для ещё открытой сделки обработать дневное закрытие и при необходимости запланировать подтверждённый выход.
4. Для входов обработать дневную точку со старой известной версией зоны. Запретить повторный вход в событии выхода и использование того же закрытия как нового входа после выхода.
5. Обновить ZigZag по завершённому H4 и создать новые зоны. Их нельзя применять к этому же или более раннему закрытию.
6. На первой последующей исполнимой котировке выполнить запланированный выход, если сделка ещё открыта.

Если одна котировка одновременно исполняет активный TP/SL и запланированный рыночный выход, для детерминированной классификации сначала обработать TP/SL; цену исполнения определяет существующая модель. В более точных данных использовать доказуемый порядок событий.

При неизвестном порядке касания TP и SL внутри OHLC-бара основной сценарий — SL первым, с флагом неоднозначности; дополнительно можно вывести TP первым. Не использовать high/low бара, начавшегося на времени подтверждения, как уже известные до решения. Учитывать гэпы и проскальзывание: стоп не гарантирует исполнение точно на уровне.

## 9. Ограничения позиций и повторный вход

- Максимум одна позиция на инструмент; без усреднения и пирамидинга.
- Одна версия зоны создаёт максимум одну сделку.
- Во время открытой позиции новые входы игнорируются, но обновления рынка и зон продолжаются.
- После любого выхода сбросить базу входного пересечения. Новый вход требует двух новых последовательных закрытий после выхода, формирующих новое пересечение в активной и ещё не использованной версии зоны.
- Не использовать пересечения, прошедшие во время предыдущей сделки, для ретроактивного входа.
- После последнего доступного события оценить оставшуюся позицию по последней исполнимой цене с причиной `end_of_data`. Если EXIT_PENDING ещё не исполнен, сохранить этот факт отдельно; не выдавать его за исполненный досрочный выход.

## 10. Числовые примеры

### SHORT

```text
H = 100; dFMZ = 10; dIMZ = 20
MZ0 = 90; MZ50 = 85; MZ100 = 80; E50 = 92.5
Дневные закрытия 94 → 92: SHORT-сигнал
Фактический вход E = 92
TP = 90
SL = 2 * 92 - 80 = 104
Риск = 12; прибыль до TP = 2; RR = 1/6
```

После входа закрытия 93 → 94 дают подтверждённый выход, если TP/SL ещё не исполнены. При исполнимой цене 94,1 после второго закрытия результат до расходов равен `92 - 94.1 = -2.1`. Закрытия 93 → 92 предупреждение отменяют. Последовательность 93 → 92 → 94 → 95 подтверждает выход только на 95.

Этот пример специально показывает, что исходный стоп может находиться даже за вершиной: формулу нельзя заменять стопом на H.

### LONG

```text
L = 100; dFMZ = 10; dIMZ = 20
MZ0 = 110; MZ50 = 115; MZ100 = 120; E50 = 107.5
Дневные закрытия 106 → 108: LONG-сигнал
E = 108; TP = 110; SL = 96
```

После входа закрытия 107 → 106 подтверждают выход. Закрытия 107 → 107,5 сбрасывают предупреждение.

## 11. Записи и отчётность

Сохранять историю candidate/zone: идентификатор ноги, версию candidate и зоны, anchor, known_time, valid_from/invalidation, MZ0/MZ50/MZ100/E50, причину изменения. Статус eventual confirmation — только диагностика.

Для сигналов сохранять обе дневные точки, их session_id, валидность/непрерывность, zone_id, E50, время сигнала, статус входа/пропуска.

Для каждой сделки сохранять:

```text
trade_id, strategy_id, instrument, direction, size
origin_zone_id, origin_candidate_leg_id, origin_anchor_price
origin_e50_price, origin_mz0, origin_mz50, origin_mz100
entry_signal_time, entry_time, entry_price
initial_tp, initial_sl, initial_risk, initial_reward, initial_RR
exit_signal_time, exit_time, exit_price, exit_reason
gross_pnl_pips, gross_pnl_currency, commission, spread_cost, slippage, net_pnl
r_multiple, mae, mfe, bars_held
warning_count, warning_reset_count
confirmed_warning_time/price/session_id
confirming_close_time/price/session_id
pending_exit_at_end, ambiguous_tp_sl, execution_mode
```

Дополнительно вести журнал всех WARNING/reset/confirmation с причиной, а не только последнюю пару. Не учитывать спред дважды, если он уже включён в bid/ask исполнения. `r_multiple` считать по исходному риску до SL.

## 12. Сравнительный прогон

На одинаковых данных, расходах и правилах позиции запустить:

| Run | Тейк | Стоп | Досрочный выход |
|---|---|---|---|
| A | MZ100 | 2E − origin_MZ100 | Нет |
| B | MZ0 | 2E − origin_MZ100 | Нет |
| C — эта стратегия | MZ0 | 2E − origin_MZ100 | Два последовательных adverse-close |

Все три — KEEP_OPEN относительно candidate. Каждый прогон полностью заново обрабатывает поток событий, освобождение позиции и последующие входы. Нельзя выдавать пересчёт выходов фиксированного исторического списка сделок за полный бэктест.

Показатели: число сигналов/входов/пропусков по причинам, TP/SL/досрочные/end-of-data выходы, win rate, средний выигрыш и убыток, gross/net P&L, profit factor, expectancy, средний R, максимальная просадка, время удержания, количество предупреждений и отмен. Отдельно показать результаты без end-of-data сделок.

Предварительные оценки по HTML (включая −127,4 пипса) не являются эталоном приёмки: там использовались фиксированные входы и proxy-исполнение. Разницу с полноценным прогоном объяснить через новые входы, календарь, цены исполнения и расходы. После реализации проверить отдельно на отложенном периоде без подбора параметров по нему.

## 13. Обязательные проверки

1. Формулы E50, ближнего TP и исходного SL соответствуют разделам 3 и 6 для LONG/SHORT.
2. При смене TP с MZ100 на MZ0 цена SL не меняется для того же входа и исходной зоны.
3. Зона, ставшая известной на H4-close, не формирует вход по предшествующим событиям или этому же закрытию.
4. Вход не использует точки разных версий зоны; equality не создаёт crossing.
5. Цена входа за MZ0 приводит к `entry_beyond_target`.
6. Первое adverse-close только создаёт WARNING; второе подряд подтверждает выход.
7. Закрытие на стороне зоны или ровно E50 сбрасывает WARNING.
8. Внутридневной возврат без соответствующего дневного закрытия не сбрасывает WARNING.
9. Выходные не разрывают соседние торговые сессии; пропуск ожидаемой сессии, невалидность и дубликат не создают ложного подтверждения.
10. Candidate update, pivot confirmation и изменение активной зоны не меняют origin_E50/TP/SL и не сбрасывают WARNING открытой сделки.
11. TP/SL до второго закрытия закрывают сделку раньше досрочного выхода; никакого двойного исполнения.
12. Подтверждённый выход исполняется только после получения подтверждения; будущий H4 high/low не используется до завершения бара.
13. После любого выхода нет входа по старому сигналу или по тому же событию; нужны две новые точки.
14. OHLC-неоднозначность отмечается и обрабатывается консервативно; гэп не заполняется фиктивно по уровню стопа.
15. Последний неполный ZigZag не превращается в подтверждённый pivot; открытые сделки и EXIT_PENDING на конце данных отражаются явно.
16. Полный прогон C пересчитывает доступность входов; результаты учитывают реальные расходы и заданный способ определения объёма.
